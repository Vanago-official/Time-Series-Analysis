## 🎯 Ідея Проєкту та Постановка Задачі

У зв'язку з регулярними загрозами з повітря критично важливо розуміти очікувану тривалість кожної оголошеної повітряної тривоги для цивільного планування, логістики та промисловості.

**Задача:** Спрогнозувати тривалість поточної тривоги (у хвилинах) у конкретному регіоні України в момент її початку ($T = \text{started\_at}$), спираючись виключно на інформацію, яка була фізично доступна до або в момент увімкнення сирени.

- **Цільова змінна ($y$):** `duration_min` — тривалість тривоги у хвилинах:
  $$\text{duration\_min} = \frac{\text{finished\_at} - \text{started\_at}}{60}$$
- **Метрики якості:**
  - **MAE (Mean Absolute Error):** середня абсолютна помилка прогнозу у хвилинах.
  - **RMSE (Root Mean Squared Error):** середньоквадратична помилка у хвилинах (штрафує великі відхилення).
  - **$R^2$ Score:** коефіцієнт детермінації.

## 🏗 Архітектура Пайплайну

Пайплайн складається з чотирьох послідовних етапів:

```
[ Історичний CSV ] 
        │
        ▼ (Етап 1)
[ Data Ingestion & Preprocessing ]  --> Очищення, дедуплікація, фільтрація, сортування за часом
        │
        ▼ (Етап 2)
[ Feature Engineering ]            --> Time, Lag, Rolling (closed='left'), Spatial
        │
        ▼ (Етап 3)
[ Time-based Split & Validation ]  --> Train (до Cutoff), Test (останні 4 тижні), TimeSeriesSplit CV
        │
        ▼ (Етап 4)
[ Modeling & Evaluation ]          --> LightGBM vs. Базові евристики, візуалізація метрик
```

### Етап 1: Збір та Очищення Даних (Data Preprocessing)
- Завантаження офіційних даних або волонтерського датасету (`official_data_en.csv`, `volunteer_data_en.csv`).
- Парсинг часових міток у формат `UTC datetime`.
- **Видалення дублікатів:** Усунення дубльованих записів тривог (у вихідному офіційному датасеті половина записів були дублікатами).
- **Суворе сортування:** Усі записи строго сортуються за `started_at` у хронологічному порядку.

### Етап 2: Генерація Ознак (Feature Engineering)
Всі ознаки формуються суворо до або в момент початку тривоги:
1. **Time Features:** година доби (`hour`), день тижня (`dayofweek`), місяць (`month`), ознака вихідного дня (`is_weekend`), тригонометричні циклічні кодування годин та місяців (`hour_sin`, `hour_cos`, `month_sin`, `month_cos`).
2. **Lag Features:** тривалість 1-ї, 2-ї та 3-ї попередніх тривог у тому самому регіоні (`lag_1_duration`, `lag_2_duration`, `lag_3_duration`), а також час від завершення попередньої тривоги (`hours_since_prev_alert`).
3. **Rolling Features:** середня, медіанна тривалість та кількість тривог за останні 3, 7 та 14 днів (`rolling_mean_3d`, `rolling_median_7d`, `rolling_count_14d` тощо).
4. **Spatial Features:** 
   - `active_nationwide`: кількість інших областей України, де тривога активна прямо зараз.
   - `active_neighbors`: кількість сусідніх областей із активною тривогою на момент старту сирени (використовує граф суміжності 25 регіонів України).

### Етап 3: Валідація та Навчання (Modeling & Time Validation)
- **Time-based Cutoff Split:** Останні 4 тижні (28 днів) виділяються як тестовий набір (Test Set). Випадкове перемішування (`train_test_split` з `shuffle=True`) суворо заборонено!
- **TimeSeriesSplit Cross-Validation:** 5-фолдова хронологічна валідація на навчальному наборі.
- **Модель:** `LightGBM Regressor` (з підтримкою `HistGradientBoostingRegressor`).

### Етап 4: Аналіз та Інтерпретація
- Порівняння з 4 базовими евристиками (Global Median, Global Mean, 7-Day Rolling Regional Mean, Lag-1 Prior Alert).
- Побудова та експорт графіків важливості ознак, розсіювання (Actual vs. Predicted) та часового ряду.

## 🛡 Гарантія Відсутності Витоку Даних (Data Leakage Prevention)

| Механізм | Реалізація | Чому витік неможливий |
|---|---|---|
| **Сортування** | `df.sort_values(by=['started_at', 'region'])` | Дані обробляються виключно в природному хронологічному порядку подій. |
| **Лагові ознаки** | `.shift(1)`, `.shift(2)`, `.shift(3)` по регіону | Використовує тільки тривалості **вже завершених** тривог, час завершення яких передує поточному `started_at`. |
| **Ковзні вікна** | `rolling(..., closed='left')` | Параметр `closed='left'` гарантує, що поточна тривога **виключена** з вікна розрахунку середнього/медіани. |
| **Просторові ознаки** | Векторизовані події $\text{start} < T < \text{finish}$ | Визначає статус активності сусідів точно в момент $T$, що відповідає публічній інформації на мапі тривог у реальному часі. |
| **Розбиття вибірки** | $\text{train}(\text{start} < \text{cutoff}) \cap \text{test}(\text{start} \ge \text{cutoff})$ | Майбутнє ніколи не потрапляє у тренувальний набір. |
| **Unit-тести** | `pytest tests/test_pipeline.py` | Автоматичні тести верифікують відсутність витоку на кожному кроці. |

## 🚀 Швидкий Старт та Локальний Запуск

### 1. Клонування репозиторію
```bash
git clone https://github.com/<your-username>/ukraine-air-raid-predictor.git
cd ukraine-air-raid-predictor
```

### 2. Створення та активація віртуального середовища
```bash
python3 -m venv .venv
source .venv/bin/activate
```

### 3. Встановлення залежностей
```bash
pip install -r requirements.txt
```

### 4. Запуск повного пайплайну
Запуск на офіційному датасеті з 5-фолдовою крос-валідацією та побудовою графіків:
```bash
python main.py
```

Запуск на волонтерському датасеті (115 000+ тривог):
```bash
python main.py --data-path data/raw/volunteer_data_en.csv
```

Додаткові опції:
- `--skip-cv`: пропустити крок крос-валідації для швидкого прогону.
- `--model hist_gb`: використати `HistGradientBoostingRegressor` замість `LightGBM`.
- `--no-spatial`: вимкнути розрахунок просторових ознак сусідніх областей.

1. `region_cat` — регіональна специфіка (область).
2. `hours_since_prev_alert` — інтервал між поточною та попередньою тривогою.
